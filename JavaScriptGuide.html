01 Introduction — The Language of the Web

JavaScript (JS) is the only programming language that runs natively in every web browser. It adds behaviour to a page: what happens when you click, what appears after a request, how data is validated, how the UI updates. If HTML is the skeleton and CSS is the skin, JavaScript is the muscle and nervous system.

What makes JavaScript different

  • Dynamic typing — variables have no fixed type; let x = 1; x = 'text'; is legal
  • Single-threaded + event loop — one call stack, but non-blocking I/O via callbacks, promises and the event loop
  • Multi-paradigm — procedural, object-oriented and functional styles all work
  • First-class functions — functions are values: pass them, return them, store them
  • Prototype-based — objects inherit directly from other objects (classes in ES6 are syntax sugar over this)

Where JavaScript runs

Browsers
V8 (Chrome/Edge), SpiderMonkey (Firefox), JavaScriptCore (Safari)
Node.js
Servers, CLIs, scripts — V8 outside the browser
Deno / Bun
Modern JS/TS runtimes with batteries included
Desktop / Mobile
Electron apps, React Native apps

A very short history

  • 1995 — Brendan Eich creates JavaScript at Netscape in about 10 days
  • 1997 — standardized as ECMAScript (ES) — JS is the language, ECMAScript is the spec
  • 2009 — ES5: strict mode, JSON, Array methods like map
  • 2015 — ES6/ES2015: the big one — let/const, arrow functions, classes, promises, modules, template literals
  • 2016 → now — one feature release every year (ES2016, ES2017 … ES2026): async/await, optional chaining ?., nullish coalescing ?? and more
Analogy: HTML decides what is on the page, CSS decides how it looks, JavaScript decides what it does. A page can work with zero JS — but every interactive product (logins, carts, feeds, maps) needs it.
💡 Tip: Learn vanilla JavaScript deeply before any framework. React, Vue and Angular are wrappers around the same DOM, events and async concepts covered in this guide — frameworks change every few years, these fundamentals do not.

02 Setup & Dev Tools Beginner

Three ways to run JavaScript

<!-- 1. External file (recommended — always) -->
<script src="app.js" defer></script>

<!-- 2. Inline block (small sites, demos only) -->
<script>
  console.log('Hello from the page');
</script>

<!-- 3. Inline attribute (avoid — mixing behaviour into HTML) -->
<button onclick="alert('hi')">Click</button>
// app.js
const button = document.querySelector('#save');
button.addEventListener('click', () => {
  console.log('Saved!');
});

defer vs async

<script src>
Blocks HTML parsing until the file loads
defer
Downloads in parallel, runs AFTER the DOM is ready, in order — use this
async
Downloads in parallel, runs as soon as it arrives — order not guaranteed (analytics)
end of <body>
Old-school approach — works, but defer is cleaner
⚠ Common beginner bug: a script in <head> without defer runs before the HTML below it exists — querySelector returns null and you get "Cannot read properties of null". Always add defer (or put the script at the end of <body>).

03 Variables & Data Types Beginner

let, const, var

const siteName = 'Laksh Guides';   // block-scoped, cannot be reassigned — DEFAULT
let theme = 'dark';               // block-scoped, will be reassigned
var old = 'legacy';               // function-scoped, hoisted, ambiguous — avoid

theme = 'light';                   // OK — let allows reassignment
// siteName = 'Other';             // TypeError: assignment to constant
  • Prefer const — signal "this never changes". Switch to let only when you must reassign
  • const is not deeply immutable — you cannot reassign the variable, but you can mutate the object/array it points to
  • var problems — function-scoped instead of block-scoped, hoisted to the top (usable before declaration as undefined), no TDZ errors. Only needed for old codebases
const user = { name: 'Laksh' };
user.name = 'Ron';        // allowed — mutating the object
// user = {};              // NOT allowed — reassigning the constant
Block scope: let and const exist only inside the nearest { } — loops, ifs, functions. This prevents the classic "loop variable leaked everywhere" bug that var had.

Primitive types (7)

string
'hello', "hi", `tpl` — text
number
42, 3.14, NaN, Infinity — binary doubles
bigint
9007199254740991n — integer beyond 2⁵³-1
boolean
true / false
undefined
declared but no value — the default
null
intentional "no value" — you assign it
symbol
unique identifier, rarely needed in app code
object
everything else — arrays, functions, dates, null!
typeof 'hi'          // "string"
typeof 42            // "number"
typeof true          // "boolean"
typeof undefined     // "undefined"
typeof null          // "object"   ← historical bug, always was
typeof []            // "object"   ← arrays are objects
typeof () => {}      // "function"

Array.isArray([])     // true — the correct array check
typeof NaN           // "number"   ← NaN = Not a Number, still a number type

Dynamic typing & coercion

let x = 1;        // number
x = 'one';      // now a string — no error

// == coerces types before comparing (avoid it)
5 == '5'       // true
0 == ''        // true  ← surprise!

// === compares type AND value (always use this)
5 === '5'      // false
5 === 5        // true
⚠ Golden rule: always use === and !==. The only time == is safe is x == null, which checks null or undefined in one shot — everything else should be strict.

Converting values

// To string
String(42)              // "42"
(42).toString()       // "42"
`42`                  // "42"

// To number
Number('42')            // 42
'42' * 1                // 42 — trick used in old code
parseInt('42px', 10)  // 42 — stop at first non-digit (pass radix 10)
parseFloat('3.5m')    // 3.5
Number('abc')           // NaN

// To boolean — only 8 falsy values exist
Boolean(0)              // false
Boolean('')             // false
Boolean(null)           // false
Boolean(undefined)      // false
Boolean(NaN)            // false
Boolean('0')            // true — non-empty string!
💡 Tip: 0.1 + 0.2 === 0.3 is false (0.30000000000000004) — all languages with binary floating point share this. For money, store paise/cents as integers (₹1 = 100) or use a decimal library. Compare floats with Math.abs(a - b) < 0.0001, never with ===.

04 Operators & Control Flow Beginner

Operators at a glance

// Arithmetic
+  -  *  /  %  **
%  = modulo (remainder) — "is even?" →  n % 2 === 0
** = exponent        →  2 ** 10 === 1024
+= -= *= /=          →  count += 1
++ --                 →  count++ (avoid inside expressions)

// Comparison
=== !==  // strict — ALWAYS use these
< > <= >=

// Logical
&&  both must be true      →  isAdult && hasId
||  at least one true      →  isAdmin || isOwner
!   negation              →  !isLoading
??  nullish coalescing     →  nickname ?? name   // only null/undefined
?.  optional chaining      →  user?.address?.city

Truthiness — the 8 falsy values

Everything in JavaScript is truthy except these eight:

false
the boolean
0, -0, 0n
zero (any form)
''
empty string
null
intentional empty
undefined
no value assigned
NaN
not-a-number
⚠ Surprises to remember: '0', 'false' and [] (empty array) are truthy — they are non-empty values. So if (value) on the string '0' passes. To check "has content", be explicit: value.length > 0.

Conditionals

if (score >= 90) {
  grade = 'A';
} else if (score >= 80) {
  grade = 'B';
} else {
  grade = 'C';
}

// Ternary — one-line if/else (readable only when short)
const label = isLoggedIn ? 'Dashboard' : 'Login';

// switch — remember break (or it "falls through")
switch (day) {
  case 'Sat':
  case 'Sun':
    isWeekend = true;
    break;
  case 'Mon':
    isWeekend = false;
    break;
  default:
    isWeekend = false;
}
💡 Tip: for 3+ related branches a switch or a lookup object is cleaner than nested else if: const icons = { sun:'☀️', moon:'🌙' }; icons[day] ?? '❓';

Loops

// Classic for — when you need the index or custom stepping
for (let i = 0; i < items.length; i++) { console.log(i, items[i]); }

// while — repeats until condition turns false
while (attempts < 3) { attempts++; }

// for...of — VALUES of any iterable (arrays, strings, maps) — PREFERRED
for (const item of items) { console.log(item); }
for (const [i, item] of items.entries()) { console.log(i, item); }

// for...in — KEYS of an object (works on arrays too — don't use it there)
for (const key in user) { console.log(key, user[key]); }

// Control
for (const n of numbers) {
  if (n % 2 !== 0) continue;   // skip odds
  if (n > 100) break;          // stop entirely
}
⚠ Never use for...in on arrays. It iterates string keys ('0', '1') and can pick up inherited properties. Use for...of, forEach or a classic for loop instead.

05 Functions, Scope & Closures Intermediate

A function is a reusable block of behaviour. In JavaScript, functions are values — you can store them in variables, pass them to other functions and return them from functions.

Four ways to write one

// 1. Declaration — hoisted (usable before its line)
function add(a, b) { return a + b; }

// 2. Function expression — created at runtime
const mul = function (a, b) { return a * b; };

// 3. Arrow function — concise, lexical `this` (ideal for callbacks)
const sub = (a, b) => a - b;
const square = n => n * n;              // single param: no parens
const noop = () => {};                   // no params: empty parens required

// 4. Async function — always returns a promise
async function loadUser(id) { return fetchUser(id); }
⚠ Arrow gotcha: a single expression body returns implicitly — n => n * n. To return an object literal, wrap it: () => ({ name: 'Laksh' }). Missing braces here is the #1 arrow-function bug.

Parameters — defaults and rest

function greet(name = 'friend', greeting = 'Hi') {
  return `${greeting}, ${name}!`;
}
greet()                  // "Hi, friend!"
greet('Laksh')            // "Hi, Laksh!"

// Rest — collects remaining arguments into a real array
function max(...nums) {
  return nums.reduce((a, b) => (b > a ? b : a), -Infinity);
}
max(3, 9, 4)            // 9

Scope & closures

Scope = where a variable is visible. Inner scopes can read outer variables; outer scopes cannot see inside. A closure is a function that remembers the variables from the place it was created — even after that place has finished running.

function createCounter() {
  let count = 0;                      // private — hidden from outside
  return {
    inc:  () => ++count,
    get:  () => count,
    reset: () => { count = 0; }
  };
}

const counter = createCounter();
counter.inc();   // 1
counter.inc();   // 2
counter.get();   // 2
// count is NOT accessible here — the closure protects it
  • Uses of closures: private state (counters, stores), function factories, memoization/caching, event handlers with captured data
  • Scope chain: global → function → block. Reading is fine up the chain; writing to an outer variable from inside is where bugs start — pass values in instead
  • Hoisting: declarations (function f(){}, var) move to the top of their scope; let/const and expressions do not — they throw ReferenceError in the temporal dead zone (TDZ)

Functions as values (callbacks)

const numbers = [1, 2, 3, 4];
const doubled = numbers.map(n => n * 2);   // [2,4,6,8] — a function passed in

button.addEventListener('click', () => {     // function given to another
  console.log('clicked');
});                                        // block of code, called later by JS

// Function factory via closure
function multiplyBy(factor) {
  return n => n * factor;
}
const double = multiplyBy(2);
const triple = multiplyBy(3);
double(5)   // 10
this in 30 seconds: regular functions get this from how they are called (obj.fn() → obj). Arrow functions have no this of their own — they inherit it from the surrounding function. That's why arrows are perfect for callbacks inside methods.

06 Arrays & Array Methods Intermediate

const fruits = ['apple', 'banana', 'mango'];
const nums   = [10, 20, 30];
const mixed  = [1, 'two', true, { id: 1 }, []];  // JS arrays can hold anything

fruits.length       // 3
fruits[0]           // "apple" — indexes start at 0
fruits.at(-1)       // "mango" — negative index from the end
fruits[fruits.length - 1]  // "mango" — old way

Transforming — map, filter, reduce

const users = [
  { name: 'Laksh', age: 20, active: true },
  { name: 'Asha',  age: 23, active: false },
  { name: 'Rahul', age: 19, active: true },
];

users.map(u => u.name)        // ["Laksh","Asha","Rahul"] — transform, same length
users.filter(u => u.active)   // 2 users                  — keep matches
users.reduce((sum, u) => sum + u.age, 0)  // 62 — fold into one value

users.find(u => u.age < 21)    // {Laksh…} — first match or undefined
users.findIndex(u => u.name === 'Asha')  // 1
users.some(u => !u.active)    // true  — at least one
users.every(u => u.age >= 18) // true  — all of them
The golden trio: map changes every item, filter removes items, reduce squashes everything into a single value (sum, object, count). Master these three and 90% of array problems shrink to one line.

Adding, removing, rearranging

push / pop
Add/remove at the END — mutates
shift / unshift
Remove/add at the START — mutates, slow
splice(i, n, ...)
Remove/insert at index — mutates, returns removed
slice(a, b)
Copy a range [a, b) — never mutates
concat / [...arr]
Combine arrays — new array
sort(fn)
Sort — MUTATES, defaults to text order
reverse()
Reverse — mutates (use [...arr].reverse())
flat(depth)
Flatten nested arrays — [[1],[2]] → [1,2]
// ⚠ sort() without a comparator sorts LEXICOGRAPHICALLY (as text)
[10, 9, 100].sort()                 // [10, 100, 9]  ← wrong
[10, 9, 100].sort((a, b) => a - b)  // [9, 10, 100]  ← numeric

// Sorting objects
users.sort((a, b) => a.age - b.age);                  // ascending
users.sort((a, b) => a.name.localeCompare(b.name));   // alphabetical

Iteration styles

items.forEach((item, i) => console.log(i, item));  // no return value

for (const item of items) { … }                  // supports break/continue

items
  .filter(u => u.active)
  .map(u => u.name)
  .sort();                                        // chaining reads like a pipeline
⚠ Mutating vs pure: push, pop, shift, unshift, splice, sort, reverse, fill change the original array — dangerous when that array is state shared with a UI (React/Vue). For immutable code, copy first: [...arr].sort().
💡 Tip: forEach cannot break out early — use a plain for...of, or the trick arr.some(x => { …; return true; }) for an early exit.

07 Objects, Spread & Destructuring Intermediate

Objects are collections of key: value pairs — the main data structure for everything shaped (a user, a product, a config, API responses).

const user = {
  name: 'Laksh',              // shorthand: same as name: name
  age: 20,
  email: 'laksh@example.com',
  active: true,
  tags: ['dev', 'student'],
  address: { city: 'Mangalore', pin: 575001 },

  // method — `this` refers to this object
  greet() { return `Hi, I'm ${this.name}`; },

  ['computed_' + 'key']: true,   // computed key
};

user.name            // dot access (keys must be valid identifiers)
user['email']         // bracket access — also for dynamic keys
const field = 'age';
user[field]          // 20

user.city = 'Udupi'; // add
delete user.active;   // remove
'name' in user      // true  — key exists check
Object.hasOwn(user, 'name')  // true — safer (ignores prototype chain)

Iterating over objects

Object.keys(user)     // ["name","age",…]   — array of keys
Object.values(user)   // ["Laksh",20,…]     — array of values
Object.entries(user)  // [["name","Laksh"],…] — [key, value] pairs

for (const [key, value] of Object.entries(user)) {
  console.log(key, '→', value);
}

// Or directly
for (const key in user) { console.log(key, user[key]); }

Destructuring — unpack values

const { name, age, role = 'student' } = user;   // default if undefined
const { name: fullName } = user;                 // rename
const { address: { city } } = user;              // nested
const { password, ...safeUser } = user;          // rest — omit one

// In function parameters (very common in React)
function renderCard({ title, subtitle = '', pinned = false }) { … }
renderCard({ title: 'Hello' });

Spread & copying

const copy   = { ...user };            // shallow copy
const updated = { ...user, age: 21 };  // copy + change (immutable update)
const merged  = { ...defaults, ...user }; // later keys win

const a = { x: 1 };
const b = a;                          // ⚠ SAME reference — not a copy!
b.x = 2;                              // a.x is also 2 now
const c = { ...a };                   // ✅ real (shallow) copy

// Deep copy (nested objects) — modern way
const deep = structuredClone(user);    // handles nested, dates, maps
const legacy = JSON.parse(JSON.stringify(user)); // functions/dates lost
⚠ Reference types: objects and arrays are compared by reference: {a:1} === {a:1} is false. This breaks includes on arrays of objects — match by a unique id instead: list.find(x => x.id === id).
JSON round-trip: JSON.stringify drops functions and undefined, converts Date to a string, and throws on circular references. For saving to localStorage or sending to an API that's exactly what you want — just remember it's a one-way trip for special types.

08 The DOM — Making the Page Interactive Intermediate

The DOM (Document Object Model) is the tree of objects the browser builds from your HTML. Every tag becomes an element node, every piece of text a text node. JavaScript reads and edits this tree, and the browser re-renders the page.

window vs document: document is the page's HTML tree; window is the whole browser context (scrollbar, timers, localStorage, global variables). window.document → the same document.

Selecting elements

// Returns ONE element or null
document.querySelector('#save');           // any CSS selector
document.querySelector('.card.title');
document.querySelector('input[name="email"]');

// Returns a LIVE HTMLCollection (use [i] or [...list])
document.getElementsByClassName('btn');
document.getElementsByName('q');

// Returns a STATIC NodeList
document.querySelectorAll('.btn');        // forEach works directly ✅

// Direct references
document.getElementById('header');
document.title;  document.body;  document.documentElement;  // <html>
💡 Tip: querySelector accepts any CSS selector you already know. Give elements id for singletons and class/data-* attributes for groups — e.g. [data-theme="dark"], [hidden].

Changing content & attributes

el.textContent = 'Hello';          // safe — escapes HTML
el.innerHTML  = '<b>Hello</b>';   // ⚠ parses HTML — NEVER with user input (XSS)

el.value;                          // for <input> / <textarea> — read
el.value = 'typed text';          // set
el.checked = true;                // checkboxes / radios
el.disabled = true;
el.hidden = true;                // boolean attribute

el.setAttribute('href', '/docs');
el.getAttribute('href');
el.removeAttribute('disabled');
el.dataset.id   // data-id → dataset.id (camelCase: data-user-id → dataset.userId)
el.classList.add('active');
el.classList.remove('active');
el.classList.toggle('active');
el.classList.contains('active');  // true/false
el.style.color = 'crimson';       // inline styles — prefer CSS classes
⚠ XSS rule: if text comes from a user, an API or a URL query — put it in textContent, never innerHTML. innerHTML with attacker data executes their scripts. Use textContent for text; if you must inject markup, sanitize it first.

Creating, inserting, removing nodes

// Create
const li = document.createElement('li');
li.textContent = 'Task 3';
li.classList.add('todo');
li.dataset.id = '3';

// Insert
list.append(li);                    // end of list (multiple args ok)
list.prepend(li);                   // start
list.append(document.createElement('hr'));
li.after(el);  li.before(el);       // siblings
list.appendChild(li);               // old API — one node only
list.insertBefore(li, list.firstChild);

// Insert HTML string (trusted content only)
list.insertAdjacentHTML('beforeend', '<li>Hi</li>');

// Remove
li.remove();                        // modern
list.removeChild(li);               // old

Traversing the tree

el.parentElement
the containing element
el.children
element children only (live)
el.firstElementChild / lastElementChild
first/last child element
el.nextElementSibling
next node at same level
el.closest('.card')
walk UP — nearest matching ancestor
el.matches('.card')
does this element match the selector?
closest + event delegation: event.target.closest('.btn') finds which button was clicked even if you clicked the icon inside it — this powers the delegation pattern in the next section.

Reading layout & geometry

el.getBoundingClientRect();   // {x, y, top, left, right, bottom, width, height}
el.offsetWidth; el.offsetHeight;         // rendered size (rounded)
el.scrollLeft; el.scrollTop;             // scroll position
window.innerWidth; window.innerHeight;   // viewport size
window.scrollY;                          // how far the page is scrolled

getComputedStyle(el).color;             // final computed CSS value

09 Events & Event Delegation Intermediate

An event is a signal that something happened: a click, a keypress, a page load. You attach a listener function and the browser calls it when the event fires.

Adding & removing listeners

button.addEventListener('click', (event) => {
  console.log('clicked!', event.target);   // event carries rich data
});

// Options object
button.addEventListener('click', handler, { once: true });  // auto-removes
button.addEventListener('scroll', handler, { passive: true }); // never blocks
button.addEventListener('keydown', handler, { capture: true }); // ancestor phase

// Remove — must be the SAME function reference
button.removeEventListener('click', handler);
⚠ Anonymous-function trap: addEventListener('click', () => work()) then later removeEventListener('click', () => work()) does nothing — they are different objects. Store the function in a variable and use it for both add and remove.

The event object

form.addEventListener('submit', (e) => {
  e.preventDefault();                      // stop page reload — essential
  const data = new FormData(e.target);
  console.log(data.get('email'));
});

input.addEventListener('input', (e) => {    // fires on every keystroke
  console.log(e.target.value);
});

input.addEventListener('keydown', (e) => {
  if (e.key === 'Enter') submit();
  if (e.key === 'Escape') close();
  if (e.ctrlKey && e.key === 's') { e.preventDefault(); save(); }
});
e.target
the element that ORIGINALLY fired the event
e.currentTarget
the element the listener is attached to
e.preventDefault()
cancel the default action (submit, link)
e.stopPropagation()
stop bubbling to parent listeners
e.key / e.code
"Enter" vs physical key position
e.timeStamp
ms since page load

Bubbling & delegation

Clicks on a child bubble up through its ancestors. Instead of one listener per item (slow with thousands of rows), attach one listener to the container:

// ✅ ONE listener for the whole list — works for items added later too
list.addEventListener('click', (e) => {
  const btn = e.target.closest('[data-action="delete"]');
  if (!btn) return;                       // clicked elsewhere
  btn.closest('li').remove();
});
💡 Why delegate? (1) one listener instead of hundreds — less memory, (2) works for elements that don't exist yet (dynamically injected rows), (3) easy teardown — remove one listener.

Common events cheat sheet

click / dblclick
mouse buttons
input / change
typing (live) vs commit (blur/select)
submit
form — always preventDefault for AJAX
keydown / keyup
keyboard
mouseenter / mouseleave
hover (don't bubble)
focus / blur
element focus (don't bubble — use focusin/focusout)
DOMContentLoaded
HTML parsed; images/styles may still load
load
everything incl. images fully loaded
window.addEventListener('DOMContentLoaded', init);

// resize / scroll — throttle with rAF or a debounce
window.addEventListener('resize', debounce(() => relayout(), 150));

10 Async JavaScript, Promises & Fetch Advanced

JavaScript is single-threaded: one thing at a time. Network requests and timers must not freeze the page, so they run "in the background" and JS continues. When they finish, the event loop runs your callback. This model is called non-blocking I/O.

Callbacks → Promises → async/await (the evolution)

// 1. Callback (old style — "callback hell" with nesting)
getUser(id, (err, user) => {
  if (err) return handle(err);
  getPosts(user, (err, posts) => {
    // nested, hard to read, hard to error-handle
  });
});

// 2. Promise — a future value with .then chaining
getUser(id)
  .then(user => getPosts(user))
  .then(posts => render(posts))
  .catch(err => handle(err))     // single place for ALL errors
  .finally(() => hideSpinner());

// 3. async/await — looks synchronous, stays non-blocking (preferred)
try {
  const user  = await getUser(id);
  const posts = await getPosts(user);
  render(posts);
} catch (err) {
  handle(err);
} finally {
  hideSpinner();
}
Promise states: pending → fulfilled (a value) or rejected (an error). A settled promise never changes again. await pauses that async function only — the rest of the page keeps running.

Creating promises

const wait = (ms) => new Promise(resolve => setTimeout(resolve, ms));

async function retry(fn, tries = 3) {
  for (let i = 0; i < tries; i++) {
    try { return await fn(); }
    catch (e) { if (i === tries - 1) throw e; await wait(2 ** i * 500); }
  }
}

Parallel vs sequential

// ⚠ Sequential — waits for each (slow: 1+1 = 2s)
const u = await fetchUser();
const p = await fetchPosts();

// ✅ Parallel — start both together (1s total)
const [u, p] = await Promise.all([fetchUser(), fetchPosts()]);

// First to finish wins (with a timeout)
const fast = await Promise.race([fetchFromA(), fetchFromB()]);

// All settle regardless of rejection
const results = await Promise.allSettled([fetchUser(), fetchPosts()]);
results.forEach(r => r.status === 'fulfilled' ? r.value : r.reason);

// Run N tasks at a time (concurrency limit)
await Promise.all(urls.map(u => fetch(u)));     // all at once
⚠ Two classic bugs: (1) await outside an async function → SyntaxError; (2) forgetting await → you pass a Promise around instead of its value, and errors silently don't reach your catch.

fetch — talking to APIs

// GET
const res = await fetch('https://api.example.com/users?limit=10');
if (!res.ok) throw new Error(`HTTP ${res.status}`);   // 404/500 do NOT throw!
const users = await res.json();

// POST with JSON body
const created = await fetch('/api/users', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'Laksh', role: 'admin' }),
}).then(r => { if (!r.ok) throw new Error('POST failed'); return r.json(); });

// DELETE / PUT
await fetch(`/api/users/${id}`, { method: 'DELETE' });

// Form data (uploads)
const form = new FormData(fileForm);
await fetch('/upload', { method: 'POST', body: form });  // boundary auto-set
⚠ fetch only rejects on network failure (offline, DNS). A 404 or 500 resolves normally with res.ok === false — you must check it yourself or errors vanish.

AbortController & timeouts

const ctrl = new AbortController();
setTimeout(() => ctrl.abort(), 5000);          // 5s timeout

try {
  const res = await fetch('/api/slow', { signal: ctrl.signal });
} catch (err) {
  if (err.name === 'AbortError') console.log('timed out or cancelled');
}

// Cancel a stale request when the user types again
let current;
async function search(q) {
  current?.abort();
  current = new AbortController();
  const res = await fetch(`/api/search?q=${encodeURIComponent(q)}`,
                         { signal: current.signal });
  return res.json();
}
💡 Tip: combine AbortController with a debounce (fire only after typing pauses) for search-as-you-type boxes. Without both, you'll render results from an old request over newer ones.

12 Modules — Splitting Code Across Files Advanced

Modules let you split a program into files with explicit imports/exports. Each module has its own scope — no accidental globals, no load-order puzzles.

Exporting

// utils.js
export const PI = 3.14159;                       // named export (preferred)
export function clamp(n, min, max) {
  return Math.min(Math.max(n, min), max);
}
export default function greet(name) { return `Hi ${name}`; }  // one per file

// Or group at the end
function a() {} function b() {}
export { a, b, a as helperA };

// Re-export (barrel files)
export * from './math.js';
export { clamp } from './utils.js';

Importing

import greet, { clamp, PI } from './utils.js';   // default + named
import { clamp as limit } from './utils.js';      // rename
import * as utils from './utils.js';               // namespace
import './side-effect.css';                       // side effects only

// Dynamic import — load on demand (code-splitting)
const { renderChart } = await import('./chart.js');

Using modules in HTML

<script type="module" src="app.js"></script>
<!-- type="module" implies defer, runs in strict mode,
     and URLs need explicit ./ or full paths -->
Module rules: (1) strict mode by default (no undeclared variables), (2) exports are live views — values update for importers, (3) imports are hoisted and loaded once, (4) you cannot import inside an if (use dynamic import()), (5) each module = one HTTP request — bundlers (Vite/webpack) merge them for production.
💡 Tip: structure code by feature, not by type — features/auth/{api.js, validators.js, LoginPage.js} keeps related code together. Export small, focused functions with clear names; a module that exports 40 things is doing too much.

⚠ Three rules: (1) storage only holds strings — everything else needs JSON.stringify/parse; (2) never store passwords/tokens meant to be secret — anything JS can read, scripts can read (an XSS bug exposes it); (3) getItem returns null when missing, and JSON.parse(null) doesn't throw — but JSON.parse('garbage') does. Wrap parses in try/catch.
// Safe helpers
function loadJSON(key, fallback) {
  try {
    const raw = localStorage.getItem(key);
    return raw ? JSON.parse(raw) : fallback;
  } catch {
    return fallback;              // corrupted entry
  }
}
function saveJSON(key, value) {
  try { localStorage.setItem(key, JSON.stringify(value)); } catch (e) { /* quota */ }
}

15 Timers, Browser APIs & Performance Intermediate

setTimeout & setInterval

const timerId = setTimeout(() => showPopup(), 3000);   // once, after 3s
clearTimeout(timerId);

const pollId = setInterval(pollStatus, 5000);           // every 5s
clearInterval(pollId);                                    // stop!

// Chaining instead of setInterval (guarantees no overlap)
function poll() {
  check().finally(() => { timeoutId = setTimeout(poll, 5000); });
}
⚠ Debounce vs throttle: debounce — run only after calls stop (search box: wait 300 ms after the last keystroke). throttle — run at most once per window (scroll handler: once every 100 ms). Without them, resize/scroll handlers fire hundreds of times per second.
// Debounce
function debounce(fn, ms = 300) {
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), ms); };
}

// Throttle (leading edge)
function throttle(fn, ms = 100) {
  let last = 0;
  return (...args) => {
    const now = Date.now();
    if (now - last >= ms) { last = now; fn(...args); }
  };
}

// requestAnimationFrame — schedule work before the next repaint (60fps)
function onScroll() {
  requestAnimationFrame(() => { parallaxY = window.scrollY * 0.5; });
}

The 10 classic pitfalls

  1. Missing === — if (value = 10) assigns instead of compares → infinite loop
  2. Forgetting e.preventDefault() on form submit → page reloads, state lost
  3. this lost in callbacks — arrow functions or bind when passing methods
  4. Async mistakes — missing await, or await in a loop when calls are independent
  5. fetch without res.ok check — 500s look like success
  6. innerHTML with user data — XSS vulnerability
  7. Mutating shared arrays/objects — UI doesn't update or state corrupts
  8. Stale closures in loops — var i captured by all callbacks; use let
  9. Memory leaks — listeners never removed, timers never cleared, detached DOM retained by closures
  10. Using == null only — otherwise strict; parseInt without radix (pass 10)
// Stale closure trap — all callbacks print 3, 3, 3 (with var)
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);

// Fixed — let creates a new binding each iteration
for (let i = 0; i < 3; i++) setTimeout(() => console.log(i), 0);   // 0 1 2
